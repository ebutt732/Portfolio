01 / PROJECT OVERVIEW

Ten screens, three audiences, no shared source of truth

FAT10 is Educative's ten most-visited screens and core navigation points — the journeys millions of learners traverse. As the platform grew, those screens accumulated hundreds of component variations built without shared governance. Three groups felt it differently:

  • 👥Learners: met different interaction patterns and hierarchy on screens that should feel the same
  • 🎨Designers: rebuilt variants from scratch and hunted for the "right" style every time
  • ⚙️Developers: maintained parallel implementations of the same component across 50+ files

My job was to turn that landscape into one system designers and developers would actually reach for — across web, mobile, and tablet.

02 / PROBLEM · CHALLENGE · GOAL

Consistency at scale

  • Design chaos – 128 component instances across FAT10 with no unification strategy.
  • Dev burden – logos, cards and accordions each reimplemented in several code modules.
  • Token explosion – a palette grown to 188 colors, many unused or near-duplicate.
  • Maintenance tax – a brand color change meant edits across 50+ files; bug fixes didn't propagate.
Goal 01

One canonical variant

Every component type resolves to a single system component — two only where layout genuinely demands it.

Goal 02

Accessible by default

WCAG compliance built into the component, not rediscovered in a page-by-page audit.

Designers were spending 3–5 days recreating work that already existed.
03 / PROCESS · EXECUTION

Audit first, then design once

Rather than a big-bang rewrite, we phased it: inventory what exists, rank it by real usage, design one canonical variant, and roll it out incrementally. Of 128 instances, 55 were targeted for Q1 — the highest-frequency, highest-impact components.

Step 01 – Audit

Grepped the codebase for color and token occurrences and cross-checked platform analytics with engineering. Ground truth on what was actually used.

Step 02 – Design · adopted

One canonical variant per component (two where full-width and two-column layouts both existed), validated against WCAG across 50+ states.

Step 03 – Roll out

New designs replaced the originals in place, so every instance across FAT10 updated automatically instead of screen by screen.

Three worked examples

Example 01

Company logos

Six treatments across course pages, landing pages and modals → two canonical variants (vertical, horizontal). One design day, one eng day.

Example 02

Content cards

Course, testimonial and feature cards each had their own internal structure → one card with composable inner elements. New card types now ship in hours.

Example 03

Accordions

Curriculum, FAQ and code-lab accordions each behaved differently → a single interaction model, standardized platform-wide.

04 / DEEP DIVE · COLOR & TOKENS

From 188 colors to a three-layer token system

The palette had grown organically for years: 188 colors, 115 tokens, three color families no component relied on, and a dark mode that was a straight copy of light. We eliminated everything with zero occurrences, folded low-usage shades into their nearest primary, and rebuilt dark mode from scratch.

Layer 1

Color palettes

Named by hue plus darkness scale — grey-50 through grey-1000. No ambiguity, clear progression.

Layer 2

Semantic tokens

Three types (background, stroke, content) × six purposes (neutral, brand, success, warning, danger, additional) — bg-primary, stroke-success.

Layer 3

Component themes

Theme tokens bind semantics to components. Pick "success" and background, stroke and text resolve themselves.

Roughly three weeks of front-loaded design and engineering work — including the dark mode rebuild and WCAG validation — that paid off across every component that followed.

06 / CONCLUSION · NEXT STEPS · LEARNINGS

What this project taught me

  1. Audit with data, not opinion.Occurrence counts settled arguments that taste never would.
  2. Standardize interaction before visuals.Variant bloat started with behavior, not styling — the accordions proved it.
  3. Adoption follows convenience.Copy-pasting a unified card takes 30 seconds; rebuilding takes a day. That's the whole strategy.

Q1 shipped 43% of core components; Q2 closed the remaining 57%. Syntax now grows with the product — new components follow its patterns and naming without a central gatekeeper.
